# 替音工具 · 前端规范（暖米黄「精装版」）

- **更新时间**：2026-10-17
- **适用范围**：`src/MkvAudioSwap.App`（Avalonia 12 桌面 UI）
- **不适用范围**：`src/MkvAudioSwap.Core`。Core 是已有实测依据的稳定层，本轮没有改它的行为。
- **一句话**：这次不是换皮肤，而是把「两段素材 → 一个成品」讲清楚；所有视觉决定都要服从产品底线和 ADR 护栏。

> 如果你只想改一个颜色或一个间距，先看 **§2.1 对比度表** 和 **§6 护栏**，再动手。
> 改完必须按 **§7 验证清单** 重新截图；主界面高度和文字对比度都不能靠估。

## 1. 设计原则

1. **暖而不软**：背景、描边、阴影可以柔和；**文字必须硬**（≥ 4.5:1）。  
   这是 ADR-016 的原话：柔和应该体现在背景和描边，不能体现在文字上。
2. **一屏一事**：主界面只做「选两个文件 → 核对 → 开始」；低频动作（偏移、设置、提醒、完成）进弹窗。
3. **颜色只给结论**：绿 = 一致/就绪，琥珀 = 请自己看一眼，红 = 物理上不可能。  
   每种颜色必须配符号（✓ / ⚠ / ⛔），色弱用户和截图传阅都能看懂。
4. **信息只出现一次**：卡片 = 文件事实；合成摘要 = 时长结论 + 输出信息；提醒 = 后果与建议。
5. **动效只做反馈**：不改变布局、不抢注意力；主窗口固定高度，任何“点开变高”的交互都不做。
6. **保留系统标题栏**：不为“看起来像现代应用”去重写窗口拖动/最大化/缩放。

### 2.3 间距、圆角、阴影

- 间距以 2/4 为基数，常用：6 / 8 / 10 / 12 / 14 / 16 / 20 / 24 / 26 / 32。

  不做“浮在空中的大投影”，也不给文字加阴影。

### 2.4 图标与空状态插画

- 所有图标是 `App.axaml` 里的 `StreamGeometry`（`IconSwap` / `IconVideo` / `IconAudio` / `IconShield` / `IconGear` / `IconFolder` / `IconFile` / `IconCheck` / `IconWarning` / `IconBlocked` / `IconInfo` / `IconChevronRight` / `IconSliders` / `IconSparkle` 等）。
- 统一用 `Path` 绘制：描边 1.5–1.7、圆头圆角；**不再用 emoji**（🎬 / 🎵 / ⚠ 这类字符在不同字体/系统下观感不可控）。
- 尺寸：9 / 11 / 13 / 14 / 16 / 18。图标与文字并排时用 `VerticalAlignment="Center"`。
- 空状态线稿：96×96 的 `EmptyVideoArt` / `EmptyAudioArt` + `Empty*Spark`，放在 96 圆形底上；内圈 72 的浅绿圆。  
  这是空状态唯一的“大图形”，不要再用 emoji 或位图代替。
- 新增图标：在 `App.axaml` 的 `Application.Resources` 里加 `StreamGeometry`，遵循 24×24 画布、2px 安全边距；不要用彩色图标。

### 2.6 动效

- 只做反馈，不做装饰性循环。
- 窗口淡入 220ms；卡片 hover 180ms；按钮 150–160ms；完成徽章淡入 260ms。
- 用 `Transitions`（`BrushTransition` / `TransformOperationsTransition` / `BoxShadowsTransition`）而不是每帧计时器。
- 主按钮 hover 只改背景，不做缩放；卡片 hover 缩放 1.003、拖拽 1.008，幅度刻意小。
- 进度条只在 `Busy` 时出现；不要给“等待”做无限旋转以外的花活。

## 3. 主界面结构

```
┌─ 顶栏：品牌 + 全程不重编码 + 设置 ────────────────────────────┐
│  ┌─ 01 源视频 [已就绪] ─┐      ┌─ 02 你的音频 [有提醒] ─┐   │
│  │ 文件名 / 体积          │      │ 文件名 / 体积          │   │
│  │ 规格 chips             │      │ 规格 chips             │   │
│  │ 源音轨 / 说明          │      │ 说明                   │   │
│  │ [更换视频]             │      │ [更换音频]             │   │
│  └────────────────────────┘      └────────────────────────┘   │
│  ┌─ 合成摘要 ───────────────────────────────────────────────┐ │
│  │ 时长检查 ✓ 时长一致 0:30   V ███████████  A ███████████ │ │
│  │ 将输出 xxx_替换音频.mkv   MKV  预计 8.7 MB  保存到 …    │ │
│  │                                        [音频偏移 无 ›]  │ │
│  └──────────────────────────────────────────────────────────┘ │
│  [⚠ 提醒 成品结尾会静音 0:22                              详情] │
│  [                        开 始                            ]   │
│  • 状态/提示（没有内容时整行塌缩）                             │
└──────────────────────────────────────────────────────────────┘
```

### 3.1 顶栏

- 左侧：品牌块（`IconSwap`）+ 标题 + 副标题 + `全程不重编码` 徽章（盾牌图标）。
- 右侧：`设置` 链接（齿轮 + 文字）。
- 不再写“画面与音质零损失”这种长句；副标题固定为“画面原样保留 · 声音换成你的”。

### 3.2 文件卡（左右各一）

- 卡片顶部：`01/02` 步骤号 + 角色（`源视频` / `你的音频`）+ 状态胶囊。
- 空状态：
  - 96 圆形线稿 + `把视频/音频拖到这里`
  - 一句角色说明（保留第 1 条视频流 / 作为成品唯一的音轨）
  - 格式 chips（MP4/MOV/MKV/M4V；CAF/WAV/FLAC/MP3）
  - “拖入文件，或点击这里选择”
  - 整块空状态可点（`Button.cardBody`），底部仍有明确的 `选择视频/音频` 按钮。
- 已选状态：
  - 文件图标块 + 文件名 + 体积
  - 规格 chips（分辨率/帧率/编码/时长；编码/采样率/位深/声道/时长）
  - 补充行（源音轨、将被替换等）
  - 拦截时：规格 chips 清空，显示红色 `dangerCard` 说明；不要在“不能处理”的文件上继续展示规格。
- 状态胶囊：
  - `已就绪`（绿，✓）
  - `有提醒`（琥珀，⚠）
  - `无法处理`（红，⛔）
  - 空状态不显示胶囊。
- 底部按钮：空状态 `选择视频/音频`；已选 `更换视频/更换音频`。

### 3.3 合成摘要

这是本轮新增的主信息区，用来回答“这次会得到什么”：

1. **时长检查**：结论符号 + 一句话 + 差值（仅一次）。
2. **双轨时间轴**（`Controls/DurationTimeline.cs`）：
   - 上轨视频（主色），下轨音频（浅绿；不一致时琥珀）。
   - 偏移会移动音频条；零点有一条细线。
   - 只有两边时长都有效时才画条；缺一边只画空轨道，避免“已经对上了”的误读。
3. **将输出**：真实输出文件名（`OutputNaming.BuildOutputPath`，不创建文件）、`MKV`、预估体积（`SizeEstimator`）、保存目录。
4. **音频偏移入口**：整块可点，显示 `无` 或 `-300 毫秒`；设过偏移后浅绿底 + 深绿字。
5. 时长不一致时，左侧出现引导语：“整体差一点？用右侧「音频偏移」校正”。

### 3.4 提醒条

- 只在有 `Caution` 级提醒时出现；摘要 + 数量 + `详情` 按钮。
- **绝不做行内展开**（ADR-018：展开会把「开始」挤出窗口）。
- 完整清单在 `NoticesDialog`，按警告在前、说明在后；每条带来源 chip。

### 3.5 开始与状态行

- `开 始` 通栏、`MinHeight=50`、`ColumnDefinitions="*"` + `HorizontalAlignment="Stretch"`（README 界面尺寸 A：不写会缩成 38px）。
- 禁用条件只两个：槽位为空，或文件里没有可用的视频/音频流（ADR-004）。
- 禁用时文字用 `#5C5449`，不是白字；图标隐藏。
- 状态行只在 `Busy` 或 `StatusLine` 非空时占位；两个文件就绪时整行塌缩（ADR-014）。
- Busy 时一行显示 `StatusText + ProgressBar + percent`；空闲时是 `• + StatusLine`。

## 4. 弹窗

所有弹窗共用：

- 顶部 32×32 图标块（`sectionTile`）+ 17px 标题 + 12px 副标题；
- 内容用 `dialogCard` / `infoCard` / `warnCard` / `dangerCard`；
- 底部按钮右对齐，主按钮 `.primary.compact`，次要 `.ghost.compact`；
- 除提醒清单外，弹窗高度随内容（`SizeToContent=Height`），不写死高度；
- 每个 Window 都设 `Icon="/Assets/app.png"`、`ShowInTaskbar=False`、`WindowStartupLocation=CenterOwner`。

### 4.1 偏移（`OffsetDialog`）

- 大号毫秒输入 + 单位的 `毫秒` + 实时 `= x 秒`（ADR-017）。
- 快捷增减：`-500 / -300 / -100 / +100 / +300 / +500`。  
  点一次是在**当前值上累加/累减**，不是把值设为按钮上的数字；所以没有 `0` 这个快捷值，归零用右上角「归零」。
- 正值/负值两块方向解释；负值箭头镜像。
- 方向示意：双轨时间轴，输入时实时移动音频条；显示“视频 0:30 · 音频 0:30”。
- 两条前提：裁过片段要重导；程序只比时长不比内容。
- 预览：`预览前 10 秒`；生成中显示 indeterminate 进度并禁用按钮；完成后状态里写本次实际偏移。
- **语义不能改**：预览必须用输入框当前值，不是上次确定的值；预览用 `atrim`/`adelay`，不是 `-itsoffset`；每次新文件名；状态里带偏移（ADR-022/023/024）。

### 4.2 设置（`SettingsDialog`）

- 保存位置：当前路径 + `更改…` + `恢复为视频所在目录`（默认时隐藏）。
  - 更改目录的起点 = **当前保存目录**；这是本轮修的低成本交互，不影响视频/音频选择框的起点（仍固定程序目录，README §18）。
- 运行环境：`检查运行环境` → `ffmpeg` / `ffprobe` 两行，带 ✓/⛔、路径、版本；失败时给“bin 是否同层 / 杀毒拦截”提示。
- 关于：一句话 + `-c copy` 说明 + 音频编码边界（FLAC/WAV/CAF 无损；MP3/AAC 提醒有损）。

### 4.3 提醒（`NoticesDialog`）

- 固定 640×540，可缩放（Min 520×380），列表滚动。
- 标题 `需要注意 N 处` 或 `N 条说明`；副标题说明“不影响操作，按钮照常可用”。
- 每条：严重度图标 + 文本 + 来源 chip（视频文件/音频文件/视频与音频之间）。
- 页脚：“程序只比对时长与规格，不判断内容对错 —— 最终以你的耳朵为准。”

### 4.4 完成（`CompletionDialog`）

- 成功徽章（✓ 圆形，260ms 淡入）+ `替换完成` + 体积/偏移详情。
- 输出路径：`SelectableTextBlock`（可选中）+ `复制路径`。
- 操作：`打开所在文件夹`（主）、`播放`、`再处理一个`。

### 4.5 失败（`FailureDialog`）

- 标题用具体错误（如“无法写入输出文件”），窗口标题固定“处理失败”。
- 红色建议卡 + 只读 TextBox（命令行 + ffmpeg 输出，180px 可滚动）+ `复制详情`。
- 备注：“详情只包含本次的命令行与 ffmpeg 输出，不包含音频内容。”
- 这是用户反馈问题的唯一信息源（README 护栏 10）；不要截断、不要只给一句抽象错误。

## 5. 状态与文案

| 状态 | 卡片 | 摘要 | 开始 | 状态行 |
|:--|:--|:--|:--|:--|
| 两个都空 | 两卡空状态 | `选好两个文件后检查时长` + 空轨道 | 灰 | `先选好视频和音频，或者把它们拖进上面的框` |
| 只差一个 | 一个有文件、一个空 | `还差一个文件` | 灰 | `还差一个视频/音频` |
| 两个就绪、时长一致 | 两个 `已就绪` | `✓ 时长一致 · 0:30` + 双轨对齐 | 绿 | 空（整行塌缩） |
| 时长不一致 | 两个 `已就绪` | `⚠ 音频短 0:22` + 引导语 + 音频条变短/琥珀 | 绿（仍可点） | 空 |
| 有质量提醒 | 对应卡 `有提醒` | 正常 | 绿 | 空；提醒条给后果 + 详情 |
| 文件被拦 | 对应卡 `无法处理` + 红说明 | `时长未知` + 空轨道 | 灰 | `有文件无法处理，请看卡片内的红色说明。` |
| 处理中 | 文件卡不变 | 正常 | 灰 | `正在封装，请稍等…` + 进度条 + % |
| 成功 | 不变 | 不变 | 绿 | 完成弹窗 |
| 失败 | 不变 | 不变 | 绿 | 失败弹窗 + 错误状态 |

**文案规则**：

- 只陈述事实，不做“验证通过/不通过”的审判式判断（ADR-004）。
- 同一个数字只在一个地方出现：时长差在摘要；后果在提醒条/提醒弹窗。
- 不用“请稍候”“正在努力”这类空话；用“正在读取文件信息…”“正在封装，请稍等…”。
- 音频不再写“必须线性 PCM”：选择框已包含 FLAC/ALAC/MP3 等；有损只提醒，不拦（ADR-020）。
- 失败文案必须能指向下一步（看 bin、换目录、复制详情）。

## 6. 护栏（不能碰）

1. **不改 Core 行为**。ffmpeg 命令构造、偏移语义、文件生命周期都在 Core；改行为先写 ADR。
2. **所有显示文字 ≥ 4.5:1**；新增颜色/背景组合必须重算；渐变底部不得暗于 `#F4EFE5`；主按钮渐变顶部不得亮于 `#4F7C66`。
3. **主窗口固定高度**，不用 `SizeToContent` 兜底；改布局后用截图 + `Content.Bounds` 实测（ADR-019）。当前 880×648 / Min 800×620 已验证不裁切。
4. **提醒不做行内展开**，必须独立弹窗（ADR-018）。
5. **「开始」按钮**必须 `ColumnDefinitions="*"` + `HorizontalAlignment="Stretch"`；否则宽度只有 38px。
6. **偏移**：入口整块可点；毫秒 + 秒；`InvariantCulture`；预览用当前输入值；`atrim`/`adelay`；新预览文件名；状态带偏移。
7. **选择框起点**：视频/音频固定 `AppContext.BaseDirectory`；输出目录选择从当前保存目录开始。两者不要混。
8. **失败详情**必须保留命令行 + ffmpeg 输出 + 复制详情。
9. **不加新 NuGet 包 / 不引 MVVM 框架 / 不改系统标题栏**。当前是手写 `ObservableObject` + code-behind 编排；要改先说明理由。
10. **不删 `Assets/app.ico` / `app.png` / `bin\ffmpeg.exe`**；后者决定发布结构（ADR-011、ToolLocator）。

## 9. 已知取舍 / 下一步

1. **不做自定义标题栏**：保留系统拖动/最大化/缩放，换取零窗口控制 bug。想要无边框品牌标题栏，另开一轮并单独验证多显示器/高 DPI。
2. **不做位图纸纹**：用暖色渐变 + 柔影 + 1px 暖线表达纸感。  
   理由：位图噪点会让文字边缘发灰、缩放糊；这个项目宁可“干净的纸”也不要“脏的纹理”。
3. **App 层仍然零单测**：本轮用截图 + UIA 冒烟代替；`MainViewModel` 仍 843 行。  
   下一步若继续投入，优先级仍是把偏移/预览/失败编排抽成可测服务，再加 App 测试工程。
4. **弹窗偏高**：偏移 ≈715、设置带环境检查 ≈710。1080p 可用区（≈1040）没问题；768p 下会顶到任务栏。  
   如果要支持小屏，下一轮把偏移/设置内容放进 `ScrollViewer` 并设 `MaxHeight`，不要把字号压小。
5. **应用图标是“播放 + 电平条”而不是“交换箭头”**：16px 下箭头容易糊成一团；播放三角 + 两根不等高电平条在 16/32px 更清楚。  
   如果更想要“交换”语义，可以另出一版，但必须同时看 16px。
6. **仍不引 MVVM 框架**：`ObservableObject` 17 行，界面状态可控；本轮只加了 `IBrush`、chips、输出摘要和状态胶囊。  
   引入 CommunityToolkit.Mvvm 需要单独说服，不在本轮范围。
