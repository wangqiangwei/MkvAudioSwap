# 生成测试素材.ps1 使用与维护说明

> 这份文档讲**脚本本身怎么用、怎么改**。
> 想知道"每个素材文件应该触发什么表现"，看生成结果里的 `说明.md`
> （那份由脚本自动写出，和实际文件永远同步）。

脚本位置：`docs\生成测试素材.ps1`
默认产出：`<仓库的上一级>\测试素材\`（21 个素材 + 1 个自动生成的 `说明.md`）

---

## 一、为什么要这个脚本

工具里有大量"分支判断"：时长不匹配、非 PCM 音频、异常位深、多音轨、损坏文件、
命名冲突……这些分支**没法靠肉眼看代码确认**，必须拿真实文件喂进去看表现。

自己剪素材很麻烦：要造出"8 位 PCM""两条音轨""拷到一半的文件"这些畸形样本，
比写工具本身还费事。这个脚本用 ffmpeg 一条命令合成一个，全都自动化。

**这些素材是测试图案 + 正弦波，不是真实音乐/画面。**
它们只负责触发判断分支，不用来评估音质或观感。

---

## 二、怎么跑

```
powershell -ExecutionPolicy Bypass -File docs\生成测试素材.ps1
```

**不需要任何参数**，也不要求你在哪个目录下执行 ——
路径全部由脚本自身位置推导（`$PSScriptRoot` 是 `docs\`，上一层就是仓库根）。

会先打印解析结果，便于确认找对了地方：

```
仓库根目录: <...>\MkvAudioSwap
输出目录  : <...>\测试素材
ffmpeg    : <...>\MkvAudioSwap\tools\ffmpeg.exe
ffprobe   : <...>\MkvAudioSwap\tools\ffprobe.exe
```

跑完约 53 MB、22 个文件。可以重复跑，会覆盖同名文件。

## 三、参数

三个参数都可省略，留空即自动推导。

| 参数 | 默认 | 说明 |
|:--|:--|:--|
| `-OutDir` | `<仓库的上一级>\测试素材` | 素材输出目录。会递归创建。 |
| `-Ffmpeg` | 自动查找 | 显式指定 ffmpeg.exe 的完整路径 |
| `-Ffprobe` | 自动查找 | 显式指定 ffprobe.exe 的完整路径 |

用参数覆盖的例子：

```powershell
# 输出到别处，并用自己装的 ffmpeg
powershell -ExecutionPolicy Bypass -File docs\生成测试素材.ps1 `
    -OutDir 'D:\临时\素材' `
    -Ffmpeg 'C:\ffmpeg\bin\ffmpeg.exe' `
    -Ffprobe 'C:\ffmpeg\bin\ffprobe.exe'
```

### 输出位置为什么默认在仓库外面

```
<某目录>\
├─ MkvAudioSwap\      ← 仓库（代码）
└─ 测试素材\           ← 素材（生成物，53 MB）
```

53 MB 的二进制生成物不该混进代码目录。父目录取不到时（例如仓库就在盘符根目录下）
会退回放在仓库根里。

### ffmpeg 去哪找

按顺序：

1. `<仓库根>\tools\ffmpeg.exe` —— `build.bat` 会把 ffmpeg 放这里
2. `<仓库根>\dist\替音工具\bin\ffmpeg.exe` —— 已经发布过的话这里也有
3. 系统 `PATH`

三个都没有会**明确报错**，并列出解法（跑 build.bat / 手动放 tools\ / 用参数指定 / 装到 PATH），
不会让你对着一个"找不到文件"发呆。

**所以推荐先跑一次 `build.bat`**，之后这个脚本什么都不用配。

## 五、怎么加一个新用例

在脚本末尾（`[12/12]` 那段之后、写 `说明.md` 之前）按现有模式追加即可：

```powershell
# ─────────────────────────────────────────────────────────────
Write-Host ''
Write-Host '[13/13] 你要测的场景' -ForegroundColor Yellow
$newFile = Join-Path $OutDir '22_文件名说明它测什么.wav'
FF @('-hide_banner','-loglevel','error',
      '-f','lavfi','-i','sine=frequency=440:sample_rate=48000:duration=30',
      '-af','aformat=channel_layouts=stereo',
      '-c:a','pcm_s16le','-n',$newFile)
Report $newFile '预期表现：拖进音频槽应……'
```

要点：

- **文件名编号 + 一句话说明用途**。用户对着资源管理器就能看懂，不用翻文档。
- `FF @(...)` 传 ffmpeg 参数数组；`-n` 表示不覆盖（脚本会先覆盖同名文件，见下）
- `Report` 会打印文件体积、视频/音频规格、音轨数，末尾再补一句"用途"
- **故意损坏的文件用 `ReportBroken`**，不要用 `Report` —— 那种文件本来就 probe 不出来，
  用 `Report` 会让 ffprobe 吐错误，既刷屏也没意义
- 别忘了同步更新脚本末尾那段 `说明.md` 文本

## 六、脚本里的坑（都是踩过的，改动前先读）

### 1. `.ps1` 必须保存为「UTF-8 带 BOM」

Windows PowerShell 5.1 在**没有 BOM** 时按 ANSI 代码页读 `.ps1`，中文全变乱码，
而且报错信息完全指不到真正原因，长得像这样：

```
Unexpected token '鐢ㄩ€?' in expression or statement.
Missing closing ')' in statement block or type definition.
```

**这个坑踩过两次**（有些编辑器/工具链保存时会悄悄去掉 BOM）。
改完脚本请确认：

```powershell
[IO.File]::ReadAllBytes('docs\生成测试素材.ps1')[0..2]   # 应为 EF BB BF
```

修法是先按 UTF-8 读进来、再用带 BOM 的编码写回：

```powershell
$t = [IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)
[IO.File]::WriteAllText($p, $t, (New-Object Text.UTF8Encoding($true)))
```

### 2. 不能用 `& $Ffmpeg @args` 直接调用

Windows PowerShell 5.1 会把**原生命令写到 stderr 的内容提升成 ErrorRecord**。
ffmpeg 的 banner 和进度都写 stderr，于是：

- 加 `2>&1 | Out-Null` —— 没用，错误记录已经产生了
- 加 `*> $null` —— 同样没用

在 `$ErrorActionPreference='Stop'` 下会直接中断脚本，报的还是 ffmpeg 的版本号（极具误导性）。

所以 `FF` 函数用 `Start-Process` 把输出重定向到文件，彻底绕开这个机制：

```powershell
$p = Start-Process -FilePath $Ffmpeg -ArgumentList $FfArgs -NoNewWindow -Wait -PassThru `
    -RedirectStandardError $log -RedirectStandardOutput 'NUL'
```

顺带好处：失败时能把 ffmpeg 的最后几行打出来。

### 3. 形参不能叫 `$Args`

`$Args` 是 PowerShell 的**自动变量**（当前函数的参数数组），不能当形参名。
用了它，函数里拿到的永远是空的，报错是：

```
Cannot validate argument on parameter 'ArgumentList'. The argument is null or empty
```

所以是 `$FfArgs`。

### 4. ffprobe 要用 `-v quiet` 而不是 `-v error`

`Report` 会对生成的文件做一次自检。用 `-v error` 时，**故意损坏的文件**会让 ffprobe
往 stderr 写 `moov atom not found`，又触发上面第 2 条的同一个问题。
用 `-v quiet` 彻底静音，并且损坏文件改用 `ReportBroken`（根本不 probe）。

### 5. 覆盖行为

绝大多数命令带 `-n`（不覆盖）。脚本假定可以覆盖，所以**重复跑之前请确认
`测试素材` 目录里没有你想留的东西** —— 脚本不会删目录，但会用同名文件覆盖。
如果你在素材目录里放过自己的文件，注意别撞名。

## 七、脚本和测试的关系

`tests\MkvAudioSwap.Tests\SampleFilesTests.cs` 会对这批素材做断言，
用来确认"每个文件应该触发什么"这句话本身没写错 —— 也就是校验 `说明.md` 的描述属实。

素材位置在那份测试里也不写死：

1. 环境变量 `MKVAUDIOSWAP_SAMPLES`（指定了但目录里没素材会**明确报错**，不静默回退）
2. 从测试程序集所在目录逐级向上找 `测试素材\`

都找不到就整组跳过（`SKIP_SAMPLE_TESTS=1` 可强制跳过），
所以**没生成过素材的机器也能正常跑 `dotnet test`**。
