# 替音工具 / MkvAudioSwap

把 MV 的画面原样保留、换成你自己的音频。**全程不重编码** —— 视频流和音频流是逐字节
拷贝过去的，画质音质零损失。

给翻唱作者用的：音频在 DAW 里按**无损**导出（CAF / WAV / FLAC），工具把它和视频封进一个新的 MKV。
有损格式（MP3 / AAC / Opus…）也能用，工具会明确提醒成品会有损。

> 你要是只想用、不想看代码：直接跳到下面的**「直接下载使用」**，
> 或者看 **[docs/使用说明.md](docs/使用说明.md)**。

## 直接下载使用（不用装任何东西）

**→ [前往 Releases 页面下载 `Windows.zip`](../../releases/latest)**

1. 解压得到文件夹，双击里面的 **`替音工具.exe`**
2. 把视频和音频拖进左右两个框
3. 点「开始」

不需要安装 Python、.NET、ffmpeg —— 都已经打包在里面了。

> ⚠️ 解压后 `bin` 文件夹必须和 exe 在同一层，**不要单独删除**。
> 它是 ffmpeg，工具靠它干活。

详细用法（DAW 导出设置、时长不一致怎么办、偏移怎么填）
看 **[docs/使用说明.md](docs/使用说明.md)**。

### 系统要求

Windows 10 / 11，64 位。

## 从源码构建

```
build.bat              # 双击即可：找 ffmpeg → dotnet publish → 组装绿色目录 → 打 zip
```

需要 [.NET 9 SDK](https://dotnet.microsoft.com/download/dotnet/9.0)。产物：

```
dist/替音工具/          绿色目录，双击 替音工具.exe
dist/Windows.zip        可直接分发的压缩包（约 45 MB），挂到 Release 上用
```

`build.ps1` 的参数（`build.bat` 会原样透传）：

| 参数 | 作用 |
|:--|:--|
| `-SkipZip` | 只生成绿色目录，不打 zip（迭代时更快） |
| `-NoPause` | 结束时不等待按键、不打开资源管理器（CI / 脚本用） |

ffmpeg 的查找顺序是 `tools\` → 系统 `PATH` → 自动从 gyan.dev 下载 essentials 构建。
`tools\` 目录被 git 忽略，所以换台机器第一次构建会自动下载。

跑测试：`dotnet test`（74 项；找不到 ffmpeg 时相关测试会自动跳过，不会失败）。

### 构建脚本为什么是 .ps1 + .bat 两层

构建逻辑全部在 `build.ps1`，`build.bat` 只是纯 ASCII 的一行转发。原因是实测过的：

- `cmd.exe` 逐字节读取 `.bat`，按 ANSI 代码页解释。**GBK 下某些汉字的尾字节是 `0x5C`（反斜杠）**，会被当成续行符，导致脚本从那里开始整体错位（实测把 `https:` 吃成了 `ttps:`，报出一堆 `'not' is not recognized` 之类的怪错）。
- 所以 `.bat` 保持纯 ASCII（可用 `[IO.File]::ReadAllBytes()` 验证最大字节值 ≤ 127）。
- `build.ps1` **必须保存为 UTF-8 带 BOM**，否则 Windows PowerShell 5.1 会按 ANSI 读它，中文变乱码。
- `build.ps1` 刻意不使用 here-string（`@"`…`"@`），减少与编码问题叠加时的解析歧义。

## 设计上的几个硬决定

这些不是为了好看，每一条都对应一个具体的失败模式。

### 1. 只有"物理上不可能"才会拦住用户

开始按钮变灰的条件**仅有两个**：槽位为空，或文件里没有视频流 / 没有音频流。

外加唯一一个"确定做不到"的编码：**裸 TrueHD**（实测 matroska 写不了头）。

时长不一致、体积过大、8 位位深、浮点 PCM、有损编码、源视频有多条音轨 —— **全部只出提醒，按钮照常可点**。

理由：目标用户是音频制作者。他们最怕的不是报错，而是程序悄悄替他们做了判断，或者反过来，因为差了 0.2 秒就不让干活。

### 1b. 音频不限于线性 PCM

判据是"**能不能不重编码地搬进 MKV**"，不是"编码本身有没有压缩"。

实测（ffmpeg n8.0，逐个 -c copy 进 matroska 并回读）：

| 类别 | 编码 | 结果 |
|:--|:--|:--|
| 未压缩 | pcm_s16le / s24le / s32le / f32le | ✓ 放行，无损 |
| **无损压缩** | **flac / alac / wavpack / tta** | **✓ 放行，仍然无损** |
| 有损 | mp3 / aac / opus / vorbis / ac3 | ✓ 放行，但黄字警示"成品会有损" |
| 装不进去 | truehd | ⛔ 硬拦 |

早期实现只认 `pcm_` 前缀，把 FLAC/ALAC 这类无损压缩也一并拦下 —— 那是错的，
实测它们同样能 copy 进 MKV，而且搬完仍然无损。

白名单之外的编码**不硬拦**（返回"不确定"，交给 mkv 封装器裁决）：
我们没法预先枚举 ffmpeg 将来支持什么，硬拦会误伤。

### 2. 颜色永远配符号

界面上允许上色的只有时长比对和告警：绿 = 一致，琥珀 = 请自己看一眼，红 = 物理上不可能。
每种颜色都配一个符号（`✓` / `⚠` / `⛔`），因为色弱用户分不清琥珀和绿，而且截图发到群里问人时符号也能看出来。

### 3. 位深不能用 `sample_fmt` 推

实测 `pcm_s24le` 的 `sample_fmt` 是 **`s32`**（24 位打包在 32 位容器里）。
按 `sample_fmt` 判断会把 24 位显示成 32 位。必须读 `bits_per_sample`，回退 `bits_per_raw_sample`。

### 4. ★ `-avoid_negative_ts disabled` 不是可选项

音频偏移为负时，音轨时间戳会变成负数。MKV 的默认行为（`avoid_negative_ts=auto`）会"修正"它 —— 但**修正方式是把视频整体往后推**，而不是裁掉音频开头。

实测（`-itsoffset -0.3` 封进 MKV）：

| 参数 | 视频起点 | 音频起点 | 结论 |
|:--|:--|:--|:--|
| 默认 | `0.300` | `0.000` | ⛔ 画面被推迟了，且**不报任何错** |
| `disabled` | `0.000` | `-0.300` | ✅ 音频真的提前了 |

删掉这个参数不会报错，只会让用户的画面偏移。`CommandBuilderTests.负偏移_必须关闭avoid_negative_ts` 守着它。

### 5. `-itsoffset` 必须紧跟在音频输入之前

`-itsoffset` 只作用于**紧跟其后**的那一个输入。写错位置不报错，只是偏移静默失效。
`CommandBuilderTests.偏移参数必须紧跟在音频输入之前` 守着它。

### 6. 用 `ffprobe` 而不是 `ffmpeg -i`

`ffmpeg -i` 的输出是给人看的文本，解析它容易在版本升级时翻车；`ffprobe -print_format json` 是结构化输出。

### 7. 输出先写 `.partial.mkv`，成功了再改名

中途失败或用户取消时，绝不留下一个看起来能用、实际是半截的 MKV。

### 8. 丢弃全部容器元数据（`-map_metadata -1`）

源容器的 `duration` 标签、creation_time 等是按**旧音轨**写的，复制到新文件可能和新音轨的实际时长冲突，某些播放器会据此显示错误的进度条。宁可少带信息，不要带错信息。

### 9. 预览会重编码，且音频不裁到 10 秒

预览是给用户检查对齐用的，必须快，所以 `-vf scale=640:-2 -preset ultrafast`。
视频截取前 10 秒，但**音频保留完整时长**：AAC 编码 5 分钟只要 1 秒左右，而"结尾有没有被切断"正是用户要靠预览检查的事情之一。

### 10. ffprobe 有 20 秒超时

只下载了一半、或头部损坏的 MKV 会让 ffprobe 永久阻塞。没有超时的话，用户点一下"选择文件"界面就永远转圈 —— 比报错更糟。

### 11. 界面只放核心动作，其余收进弹窗

主界面只有：**左右两个文件框 + 一个通栏「开始」按钮**，外加时长条（里面挂着偏移入口）和右上角「设置」。

- 偏移设置 → 独立弹窗（低频，且需要解释说明）
- 保存位置、运行环境检查、关于 → 「设置」弹窗
- 完成结果 → 完成弹窗

理由：初版把选择/更换/时长/偏移/预览/开始/保存位置/完成/环境检查九件事塞在一屏里，主次全无。
低频功能和"完成后才需要看的信息"都不该占主界面的位置。

### 12. 信息不重复，一行只承担一件事

初版最明显的问题是同一句话说三遍：源音轨信息在视频框里出现两次；采样率不一致在音频框、时长条、提醒区各出现一次。

现在的分工是固定的：

| 位置 | 只负责 |
|:--|:--|
| 卡片第一行 | 文件名 |
| 卡片规格行 | 用户需要核对的导出参数 |
| 卡片补充行 | 源音轨 / 容器 / 流序号 |
| 卡片备注区 | 只有"丢掉的比显示的多"这类额外信息 |
| 时长条 | 时长结论（差值在这里给一次） |
| 提醒区 | 后果与建议（不再重复差值） |

### 13. 状态行只在有内容时占位

「开始」按钮下方那行，两个文件都就绪时**完全不显示**（连空白都不留，整行塌缩）。

理由：按钮是通栏高亮的，"开始"两个字含义自明，下面再挂一句"可以开始了"只是视觉噪音。
这一行只在真正需要引导时出现（还没选文件 / 只差一个 / 文件不能处理 / 处理中 / 出错）。

### 14. 卡片内容垂直居中

卡片有 `MinHeight`，但内容比卡片矮，所以内容**必须居中**。

初版是顶端对齐，结果是卡片上半部有内容、下半部一大片死白，"空"得很明显。
试过用更多信息去填（加帧率、像素格式、码率、体积），有帮助但治标；
改成居中后空白被均分到上下，视觉上自然了 —— 空状态本来就是居中的，两者行为也终于一致。

### 15. 所有显示出来的文字对比度必须 ≥ 4.5:1

这是被用户直接指出的问题："设置里的字和背景对比度不明显，看着很累"。

初版的次要文字是 `#8C8375`（对米黄底 3.4:1）、最浅提示是 `#A79E8E`（2.4:1），**都低于 WCAG AA 的 4.5:1**。

现在分三档，每档都达标（相对 `#F5F1E8` 计算）：

| 层级 | 色值 | 对比度 | 用途 |
|:--|:--|:--|:--|
| 第一层 | `#2E2923` | 11.0:1 | 正文、标题、文件名 |
| 第二层 | `#6F6659` | 5.3:1 | 说明文字、标签 |
| 第三层 | `#7A7164` | 4.9:1 | 规格行、元信息 |

**改任何文字色值前请重新核对这张表。** 浅灰很好看，但不该用在需要读的文字上。

### 16. 时长不一致时主动把用户引到偏移功能

时长条左侧给差值，中间给一句引导："如果只是整体差了一点，可以用右侧「音频偏移」校正"。

理由：偏移是低频功能，用户看到"音频短 0:05"时未必知道旁边那个入口就是为这种情况准备的。
引导语只在差值超容差时出现，正常情况不占位。

### 17. 偏移入口整块可点，输入同时给毫秒和秒

- 时长条右侧的偏移入口是一个整体按钮（"音频偏移 + 值 + ›" 都算命中区），
  不再是只有那个"无"字能点的小链接；设过偏移后整块变浅绿底。
- 偏移弹窗里输入毫秒时，**旁边实时显示等价的秒**（`-300` → `= -0.3 秒`）。
  理由：用户量到的偏差通常是"0.3 秒"这个量级，只给毫秒他要在脑子里除一次 1000。

## 界面尺寸上的两个实测坑

这两个不是审美问题，是会让界面坏掉的技术问题。

### A. 按钮不写 `HorizontalAlignment="Stretch"` 会缩成小方块

主按钮放在 `RowDefinitions="Auto,Auto"` 且**没有声明列**的 Grid 里时，会被按内容测量。
实测 `StartButton Bounds = 0,16,38,50` —— 宽度只有 **38px**，贴在左边。
修复方式：显式声明 `ColumnDefinitions="*"` + `HorizontalAlignment="Stretch"`（修好后是 836px）。

### B. `SizeToContent="Height"` 与实际布局差 36px，会切掉底部

实测：`ClientSize = 880x560`，`Content.Desired = 404`，但 `Content.Bounds.Height = 368`。
`SizeToContent` 按 DesiredSize 定窗口高度，实际布局又给了不同的高度，
结果是「开始」按钮和状态行被切在窗口外，底部漏出一条背景。

所以窗口用**固定高度 560**（内容实测需要 524），并保留 `CanResize`。
以后加内容请重新量一次，别靠估算：`Content.Desired` 必须 ≤ `Content.Bounds.Height`。

## 测试

```
dotnet test
```

74 个测试，分两类：

**逻辑与命令构造**（不依赖外部文件）—— 偏移语义、命名去重、错误翻译、ffprobe JSON 解析、
`-avoid_negative_ts` 是否在位等。这些锁住的是"踩过的坑"，改坏了会立刻红。

**真实 ffmpeg 端到端**（找不到 ffmpeg 时静默跳过）：

- `两个流都必须逐字节不变地拷进输出` —— 用 CRC 直接证明零重编码，而不是相信 `-c copy` 会生效
- `负偏移_音频提前且视频起点保持不动` —— 守着 ADR-002
- `正偏移_音频推到后面且视频不动`
- `源视频自带音轨会被新音频替换而不是并存`
- `音频较短时输出仍保留完整视频长度`
- `成功后不留临时文件`

测试素材全部由 ffmpeg 现场合成（`testsrc` / `sine` / `anullsrc`），仓库里不放二进制。

### 手工测试素材

```
powershell -ExecutionPolicy Bypass -File docs\生成测试素材.ps1
```

会生成 21 个**故意带问题**的文件（约 53 MB），每个针对一个具体故障模式：
时长不一致、无损压缩与有损编码、8 位/浮点/低采样率、
多音轨、损坏文件、命名冲突等。配套的 `说明.md` 列了每个文件的预期表现。

**不需要传任何参数**，路径全部由脚本自身位置推导：

| 项 | 默认值 |

| 覆盖方式 | `-OutDir` / `-Ffmpeg` / `-Ffprobe` 三个参数都可以显式指定 |

对照清单 `说明.md` 也是这个脚本写的（不是单独维护的文档），保证它和实际生成的文件永不脱节。

**两份文档分工**：

| 文档 | 讲什么 |
|:--|:--|
| `<输出目录>\说明.md` | 每个素材文件应该触发什么表现（**自动生成**，跟着素材走） |
| [docs/生成测试素材.md](docs/生成测试素材.md) | 脚本怎么用、参数怎么传、怎么加用例、里面有哪几个坑 |

> ⚠️ **改这个脚本后请确认它以「UTF-8 带 BOM」保存。**
> Windows PowerShell 5.1 在没有 BOM 时会按 ANSI 代码页读 `.ps1`，中文全部变乱码，
> 报错信息还完全指不到真正的原因（表现为 `Unexpected token` 之类）。
> 检查方法：`[IO.File]::ReadAllBytes('docs\生成测试素材.ps1')[0..2]` 应为 `EF BB BF`。
> 注意有些编辑器/工具链在保存时会悄悄去掉 BOM —— 这个坑我踩过两次。
> 脚本里另外两个坑（原生命令的 stderr 会被提升成异常、形参不能叫 `$Args`）
> 也一并记在那份文档里。

`tests\MkvAudioSwap.Tests\SampleFilesTests.cs` 会对这批素材做断言，
用来确认"每个文件应该触发什么"这句话本身没写错。素材位置不写死：

1. 环境变量 `MKVAUDIOSWAP_SAMPLES`（指定了但目录里没素材会**明确报错**，不静默回退）
2. 从测试程序集所在目录逐级向上找 `测试素材\`

找不到就整组跳过（设 `SKIP_SAMPLE_TESTS=1` 可强制跳过），所以换台机器也能跑 `dotnet test`。

## 已知限制

- **只支持 Windows x64。**
- **一次只处理一个视频 + 一个音频。** 拖入多个时按类型各取第一个，
  并在状态栏说明忽略了几个（不做队列）。
- **只按 `1:v:0` 和 `1:a:0` 取流**，不提供流选择界面。
- **不做音频对齐分析**：只比对时长，不比对内容。偏移需要用户自己听、自己调。
  （测试素材 `13_音频前3秒是静音_工具查不出.wav` 就是专门演示这个边界的。）
- **自包含发布的代价**：绿色目录根层有 200 多个文件（.NET 运行时 + Avalonia 依赖），用户只需要看 `替音工具.exe` 和 `bin\`。使用说明里已注明不要删。
- **预览与正式输出的时间戳行为可能不同**（预览是 mp4 重编码，正式是 mkv 拷贝），所以预览走的是和正式输出相同的偏移参数，看到的就是出来的样子。
